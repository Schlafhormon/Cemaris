# Schritt 18 – Cemaris als eigenständiges Produkt

Datum: 21.10.2026. Auftrag: Produktbereinigung für deutsche kommunale
Friedhofsverwaltung nach abgeschlossener Portierung; geprüfte Änderungen
anschließend auf SRV-UbuntuApp mit Datenbank auf SRV-SQL02 bereitstellen.
EDWALT bleibt ein gesonderter Auftrag.

## Änderungen

- ConsignO, Dynamics GP/Diamond, Sunrise-Portal, Find a Grave und ntfy auf
  ausdrückliche Betreiberentscheidung aus aktiven Modulen, Routen, Jobs,
  Oberfläche und Konfiguration entfernt. Zugehörige reine Integrationstests,
  Fixtures und ausführbare Adapterproben entfernt. Die beiden Portalberichte
  entfallen: 43 aktive Berichte bleiben.
- Migration 0002 entfernt gespeicherte ConsignO-Zugangsdaten samt Vorwerten
  und den alten Portalsynchronisationsfehler. Alte Sessioninhalte werden nicht
  mehr als Benutzereinstellungen ausgeliefert.
- Deutsch als Sprachfallback, vollständige synchronisierte DE/EN-Kataloge,
  übersetzte Fachtexte, Einstellungen, Fehlermeldungen und Berichtsbezeichnungen.
  Euro mit lokaler Zahlformatierung, deutsche Datumsanzeige und Montag als
  Wochenbeginn in der deutschen Kalenderansicht. Keine Geldumrechnung.
- Deutsche Adressbeschriftungen und Reihenfolge PLZ/Ort. Migration 0003 erweitert
  Ort und Bundesland auf 100 UTF-16-Einheiten und übersetzt ausschließlich
  unveränderte `databaseInit`-Stammdaten. Eigene Stammdaten und Ortsvorgaben
  bleiben bestehen. Kontaktadressen erlauben weiterhin internationale PLZ.
- Standarddrucke in Deutsch, Euro, 24-Stunden-Zeit und DIN A4. Zusatzfelder
  und Kommentare im Vertragsdruck werden tatsächlich ausgegeben: die Quelle
  verwendete hierfür unzutreffende Eigenschaftsnamen. Eigene EJS-Vorlagen
  bleiben unterstützt; Lizenz- und Copyright-Hinweise erhalten.
- Sunrise-Hilfelinks entfernt. README, technische Dokumentation und
  Arbeitsanweisung beschreiben Cemaris als Produkt. Version 0.2.0, getrennte
  Imagetags ermöglichen das Aufbewahren der früheren 0.1-Artefakte.

## Herkunft und bewusste Abweichungen

Quellstand bleibt Sunrise `451ce034863b16502484367044f3e9b65370111a`.
Belege aus Portierung 03/04/06/09/11/12/13/14/16/17 bleiben historische
Nachweise. Heutige Zielpfade stehen im Quellinventar und UMFANG; entfernte
Funktionen sind als Produktentscheidung gekennzeichnet, ihre vorherigen
Zuordnungen bleiben in `historical_mapping_16` erhalten. Auf diesem Server
fehlt der optionale Referenzcheckout; er wurde nicht nachinstalliert.

Wesentliche Zielpfade: `frontend/src/`, `frontend/public/locales/`,
`backend/cemaris/`, `backend/printing-runtime/views/`, Alembic 0002/0003,
`compose.yaml`, `.env.example`. Die eingefrorene Migration 0001 bleibt
unverändert. Unbenutzte Portal-/Memorialspalten und `OrderForms` bleiben zur
verlustfreien Bestandsaktualisierung reserviert; es gibt dafür keine aktive
Integration oder Portalschnittstelle. Frühere Quellfixtures werden nicht
umgeschrieben; Produktdrucke besitzen gesonderte Goldens.

Zusätzlich zur Bereinigung wurde ein in den SQL-2022-Fällen nachgewiesener
Suchfehler behoben: `_` in Präfix-/Suffixsuchen zählt ergänzende Unicodezeichen
nun als einen Codepunkt. Der Vergleich bleibt binär genau, normale Suchen
bleiben unverändert. Weitere Behauptungen einer vollständig neuen deutschen
Such-/Gebührenfachlogik werden daraus nicht abgeleitet.

Die Vollsuite meldet zwei bestehende DeprecationWarnings in ldap3/pyasn1
(`tagMap`/`typeMap`), keine Testfehler. Ein vollständiger ursprünglicher
Sunrise-/Cypress-/Axe-Lauf, ein echter Firefoxdruck und physisches GPS wurden
nicht neu ausgeführt. Diese Grenzen sind keine ausstehenden Liveprüfungen
der ausdrücklich entfernten Anbindungen.

Tatsächliche Prüfbefehle (Arbeitsverzeichnis Repository, geheime Test-URL nur
in der privaten `test.env`):

```bash
docker run --rm --network cemaris-product-test --env-file .local/product/test.env \
  -e CEMARIS_AUTH_SESSION_DIRECTORY=/tmp/sessions \
  -v /opt/apps/cemaris:/workspace:ro --entrypoint python \
  cemaris-product-qa:20261021 -m pytest tests -q --tb=short -p no:cacheprovider
docker run --rm --user 0:0 -v /opt/apps/cemaris/frontend:/work \
  -v /opt/apps/cemaris/deploy:/deploy -w /work \
  --entrypoint npm cemaris-web-build:0.1.0 test
docker compose build --pull api web
docker compose config --quiet
python3 scripts/check_scope.py --complete --repository-only
```

Das QA-Image ergänzt die gesperrten Dev-Abhängigkeiten zum vorherigen API-Image;
Projektquellen werden aus dem Repository eingebunden. Die Drucklaufzeit wurde
über einen ausschließlich lokal verwendeten `node_modules`-Symlink mit den
Imagepaketen verbunden, anschließend entfernt. Auf dem Host sind weder Node
noch uv nötig. Browsernachweise verwenden `cemaris-browser-qa:20261021` und
`frontend/scripts/product-browser.mjs`. Private Logs/Screenshots und
Vor-/Nachabgleich stehen in `.local/product/`, die drei A4-Referenz-PDFs unter
`/tmp/cemaris-print-qa-20261021`.

### Tatsächliches Deployment

Vorherige Dateisicherung:
`backups/20261021T134805Z-9b97608329eb`, Manifest vollständig und
Prüfsummen erstellt. Das Sicherungsskript ermittelt jetzt die tatsächlichen
Container-Image-IDs statt der bereits vorbereiteten Kandidatentags. Alte
0.1-Images bleiben vorhanden. **Files-only**, kein neuer SQL-Backup-/Restoretest;
die externe SQL-Sicherung bleibt das festgelegte Betreiberverfahren.

```bash
python3 deploy/backup-files.py
docker compose stop web api
docker compose run --rm --no-deps migrate
docker compose up -d --wait --wait-timeout 180
docker compose exec -T api /app/.venv/bin/python /app/deploy/readiness.py --http
```

Server-.env um entfernte Integrationsschalter bereinigt; Imageversion 0.2.0
und deutsche Adressvorgabe ausdrücklich gesetzt. Sonstige Zugangsdaten,
Cookie-/Proxy-/HTTP-Entscheidungen und Sicherungsbetrieb erhalten.
Die reale Browserprüfung erfolgte zusätzlich auf
<http://srv-ubuntuapp.stadtdk.local/cemaris/> mit dem vorhandenen synthetischen
Vertrag. Keine zusätzlichen fachlichen Produktivdaten angelegt; Prüfzugang
anschließend abgemeldet. Fahrtwerk bleibt erreichbar. Die endgültigen Image-IDs
und Betriebsübergabe stehen in SERVER_DEPLOYMENT.md. Kein Push, kein EDWALT-Import.
Die separate SQL-Testinstanz, das QA-Netz und ausschließlich die QA-Volumes
wurden nach Abschluss entfernt; produktive Volumes bleiben erhalten.

## Verbleibende Punkte

- EDWALT-Import noch nicht begonnen; synthetische Daten bleiben gekennzeichnet.
- HTTPS und zertifikatsgeprüftes SQL-TLS sind weiterhin die vom Betreiber
  zurückgestellten Betriebsanpassungen. Keine pauschale Produktivfreigabe.
- Aufnahme von Cemaris in bestehende externe SQL-Sicherungen sowie
  Aufbewahrung/Offsite der Dateiarchive betrieblich bestätigen. Keine neuen
  SQL-Backup-/Restoretests gemäß bestehender Betreiberentscheidung.
- Kommunale Satzungen, Gebühren, Nutzungszeiten und Rollen an den tatsächlichen
  Abläufen abnehmen. Die Bereinigung erfindet keine örtlichen Fachregeln.
- Auslandsadressen haben weiterhin die historischen maximal sieben PLZ-Zeichen
  und kein eigenes Länderfeld. Reservierte Altschemaspalten können später
  unabhängig von der entfernten Laufzeit konsolidiert werden.
